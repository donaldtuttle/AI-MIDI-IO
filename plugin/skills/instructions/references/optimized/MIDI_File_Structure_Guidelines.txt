MIDI File Structure Guidelines.txt

### 1. MIDI File Header and Tracks:
• Use the MIDI file header (b'MThd') and track header (b'MTrk') to begin each file and track.
• Support multi-track MIDI files, with correct track length and tempo settings.
### 2. Meta Events and Note Events:
• Set the tempo using MetaMessages for tempo changes, and define note events using Note On (0x9x) and Note Off (0x8x).
• Ensure timing (delta times) is properly encoded using variable-length encoding (write_varlen()).
### 3. Example MIDI Code:
## Provide users with Python code that outputs valid MIDI files.

# Correct handling of delta time to stay within the 0-255 byte range
def write_varlen(value):
    buffer = value & 0x7F
    while (value >> 7) > 0:
        value >>= 7
        buffer <<= 8
        buffer |= ((value & 0x7F) | 0x80)
    result = []
    while True:
        result.append(buffer & 0xFF)
        if buffer & 0x80:
            buffer >>= 8
        else:
            break
    return result

# Set time signature to 4/4

# Define drum notes for shuffle rhythm (triplets)

snare = 38  # Acoustic Snare
hihat_closed = 42  # Closed Hi-hat

# Time between triplets in a shuffle pattern (240 ticks per beat divided by 3)
triplet_length = 160  # 1/3 of 480 ticks (quarter note)

# 2 bars of jazz shuffle
for _ in range(8):  # 8 beats (2 measures of 4/4)
    # Kick on the first triplet
    midi_data.extend([0x00, 0x99, kick, 0x40])  # Note On (Kick, velocity 64, channel 10)
    midi_data.extend(write_varlen(triplet_length))  # Correct handling of triplet length
    midi_data.extend([0x89, kick, 0x40])  # Note Off (Kick)

    # Hi-hat on the first and third triplet
    midi_data.extend([0x00, 0x99, hihat_closed, 0x40])  # Note On (Hi-hat, velocity 64)
    midi_data.extend(write_varlen(triplet_length * 2))  # Correct handling of triplet length * 2
    midi_data.extend([0x89, hihat_closed, 0x40])  # Note Off (Hi-hat)

    # Snare on the third triplet
    midi_data.extend([0x00, 0x99, snare, 0x40])  # Note On (Snare, velocity 64)
    midi_data.extend(write_varlen(triplet_length))  # Correct handling of triplet length
    midi_data.extend([0x89, snare, 0x40])  # Note Off (Snare)

midi_data.extend([0x00, 0xFF, 0x2F, 0x00])  # End of Track Meta Event

# Calculate track length and update the placeholder
track_length = len(midi_data) - track_start_index - 4

import sys

def hex_to_midi(hex_file, midi_file):
    with open(hex_file, 'r') as f_in:

    # Remove comments and semicolons

### **Best Practices for Formatting MIDI Files**

1. **General MIDI Structure**
   - **Header Chunk (`MThd`)**: This is always the first chunk in a MIDI file and defines the overall file structure.
     - **File Format**:
       - **Format 0**: All events are in a single track (for simple sequences).
       - **Format 1**: Multiple tracks in synchronization (for multi-instrument compositions).
       - **Format 2**: Independent multi-track (less common, avoid if interoperability is required).
     - **Number of Tracks**: Specifies how many tracks are in the file.
     - **Time Division**: Set the timing resolution, often 96, 240, or 480 ticks per quarter note. Use a higher resolution (like 480 or 960) for more complex rhythmic precision.

   **Example of Header Chunk**:
   ```hex
   4D 54 68 64 00 00 00 06 00 01 00 02 00 60  // Type 1, 2 tracks, 96 ticks/quarter note
   ```

2. **Track Chunks (`MTrk`)**
   - **Start of Track**: Every track starts with the identifier `MTrk` followed by the length of the track in bytes.
   - **Delta Time**: Use delta time to specify the delay before each event in the track. Make sure to use variable-length encoding for delta times.

   **Example**:
   ```hex
   4D 54 72 6B 00 00 00 XX  // Start of Track Chunk
   ```

3. **Essential Meta Events**
   - **Set Tempo (`FF 51 03`)**: Every MIDI file should have a tempo meta event that defines the tempo in microseconds per quarter note.
     - Convert from BPM to microseconds per quarter note using: `60000000 / BPM`.
     - Ensure the tempo event appears early in the track.
   
   **Example for 120 BPM**:
   ```hex
   FF 51 03 07 A1 20  // Tempo = 500,000 microseconds per quarter note
   ```

   - **Time Signature (`FF 58 04`)**: Define the time signature if it differs from the default 4/4.
   
   **Example for 4/4 time**:
   ```hex
   FF 58 04 04 02 18 08  // Time signature: 4/4
   ```

   - **End of Track (`FF 2F 00`)**: Every track must end with this meta event. Not including this can cause playback issues.
   
   **Example**:
   ```hex
   FF 2F 00  // End of Track
   ```

4. **MIDI Events (Notes, Control Changes, Program Changes)**
   - **Note On (`9X`)**: Turn on a note with a specific velocity. Always pair with a **Note Off** event.
     - `X` is the channel number (0–15), with `9X` representing Note On.
     - Follow with the note number and velocity.
   
   **Example**:
   ```hex
   90 3C 40  // Note On, channel 1, middle C (60), velocity 64
   ```

   - **Note Off (`8X`)**: Turn off the note, ensuring proper note release.
   
   **Example**:
   ```hex
   80 3C 40  // Note Off, channel 1, middle C (60)
   ```

   - **Program Change (`C0`)**: Switch instruments or sound patches within General MIDI, essential for assigning the correct sounds.
   
   **Example for Acoustic Grand Piano**:
   ```hex
   C0 00  // Program change to acoustic grand piano (Program 0)
   ```

5. **Channel Assignments**
   - **Channel 10**: Reserve this for percussion in General MIDI, with drums mapped to specific MIDI notes.
   - **Melodic Instruments**: Assign other channels (1–9, 11–16) for melodic instruments and ensure consistent mapping across tracks.

6. **Handling Polyphony**
   - Ensure multiple Note On messages are handled appropriately for polyphonic instruments. Use unique Note On/Off pairs to avoid stuck notes or improper releases.

7. **Handling Velocity**
   - Velocity values (0–127) control note dynamics. Use a variety of velocities to create expressiveness and humanize performances.

8. **Event Timing (Delta Times)**
   - **Variable-Length Encoding**: Use proper variable-length encoding for delta times. This ensures that the timing between events is preserved across different MIDI devices.

9. **MIDI File Length**
   - When specifying the length of a track chunk, ensure that it accurately represents the number of bytes in the track data. Incorrect lengths can corrupt the file.

10. **Instrument Mapping and Sound Consistency**
    - Use General MIDI sound patches (program changes) to ensure consistent playback across different devices. For non-standard instruments, provide program change messages early in the track.

11. **Avoiding Common Issues**
    - **Missing End of Track (`FF 2F 00`)**: Not adding this can cause the file to keep playing or crash in certain players.
    - **Incorrect Delta Times**: Improperly encoded delta times can desynchronize events, leading to timing issues.
    - **No Program Change**: Ensure program changes are used to set the correct instrument, especially in multi-track compositions.
    - **Too Low Resolution**: A low timing resolution (e.g., 24 ticks per quarter note) can result in choppy or imprecise rhythms.

12. **File Compatibility**
    - Test the MIDI file in multiple players or DAWs to ensure it plays back correctly across platforms.
    - If using System Exclusive (SysEx) messages or advanced MIDI features, ensure the target device supports them.

Track Identifier: 4D 54 72 6B.

Delta Times: Time offsets in ticks between events. This keeps events in sync with the MIDI clock.
Example of track start: 4D 54 72 6B 00 00 00 xx
3. Essential Meta Events:
Incorporate these meta events to ensure compatibility across all DAWs and MIDI devices:

Define the time signature of the piece. Example for 4/4 time: FF 58 04 04 02 18 08 (numerator=4, denominator=4, 24 MIDI clocks per metronome click, 8 notated 32nd notes per MIDI quarter note).
Key Signature (FF 59 02):

Define the key of the composition.
Example for C major: FF 59 02 00 00 (0 flats, major).
End of Track (FF 2F 00):

Marks the end of a track. Every track must end with this meta event.
Example: FF 2F 00.

Program Change (C0, C1, etc.):
Change the instrument on a given channel (from the General MIDI sound set).

Control Change (B0, B1, etc.):
Control various parameters like volume, pan, and modulation.

Note On (9X):

Note Off (8X):

For a full MIDI composition with multiple instruments (e.g., drums, bass, synth), each instrument should have its own track. Here’s how to structure the tracks:

Track 1: Drums (Channel 10 by General MIDI standard)

Each event is preceded by a delta time, which defines the delay (in ticks) from the previous event.
