1. Overview of MIDI Structure (Events, Channels, Messages)
plaintext

MIDI (Musical Instrument Digital Interface) is a technical standard that describes a protocol, a digital interface, and connectors for connecting electronic musical instruments, computers, and other related devices. It allows different hardware and software to communicate and synchronize.

**Key Elements of MIDI:**

- **Events**: 
   - MIDI data is made up of events. These events describe when a note is played, how hard it is played, when it stops, and how different controls are manipulated. 
   - Examples of events: Note On, Note Off, Control Change, Pitch Bend.
  
- **Channels**: 
   - MIDI allows for 16 separate channels per interface, meaning that up to 16 different instruments can be controlled by a single MIDI interface. Each instrument can be assigned to a specific channel (1–16).
   - Channels handle polyphony, allowing multiple notes or events to be sent on the same or different channels.
   - Channel messages are classified into channel voice messages (Note On/Off, Polyphonic Key Pressure) and channel mode messages (e.g., All Notes Off).

- **Messages**: 
   - A MIDI message is the smallest unit of data in MIDI and is made up of a **status byte** and one or two **data bytes**.
   - **Status Byte**: Identifies the type of message (e.g., Note On/Off, Control Change) and the channel number.
   - **Data Bytes**: Provide additional information for the status byte, such as the note number or control value.
   - Example: For a "Note On" event, the status byte would be `0x90` (Note On, Channel 1), followed by two data bytes for note number and velocity.
   
   MIDI messages are categorized as:
   - **Channel Voice Messages**: Notes, pressure, and control data affecting the sound.
   - **System Common Messages**: Time and song-related data.
   - **System Exclusive Messages (SysEx)**: Device-specific messages often used for custom manufacturer data.
2. Common MIDI Protocols and Standards (General MIDI, MIDI 2.0)
plaintext

MIDI standards have evolved over time, ensuring backward compatibility while providing more capabilities.

1. **General MIDI (GM)**
   - General MIDI is a standard extension of MIDI that defines a fixed set of sounds (programs) and drum maps, ensuring that MIDI files sound consistent across different devices.
   - **Instrument Patch Map**: General MIDI supports 128 standard instrument sounds (patches) ranging from piano to percussion, each assigned a specific program number (0–127).
   - **Percussion Mapping**: Percussion sounds are standardized on Channel 10.
   - **Control Changes**: Includes controls like volume (CC7), pan (CC10), and modulation (CC1).
   - **Polyphony**: General MIDI requires devices to support at least 24 simultaneous voices.

2. **MIDI 2.0**
   - MIDI 2.0 builds on the original MIDI protocol, offering higher resolution and more expressive control over musical performances.
   - **High-Resolution Control**: 32-bit precision for note velocities and control messages, allowing for finer control over nuances like dynamics and articulation.
   - **Property Exchange**: MIDI 2.0 allows devices to exchange metadata, such as instrument profiles, settings, and more.
   - **Enhanced Channel Range**: MIDI 2.0 supports more than the 16 traditional MIDI channels.
   - **Backward Compatibility**: MIDI 2.0 is designed to work seamlessly with MIDI 1.0 devices, ensuring interoperability between old and new devices.
3. File Formatting: How MIDI Files are Read and Written
plaintext

MIDI files are a universal standard for storing sequences of MIDI events, typically using the .mid extension. The files contain structured data that digital audio workstations (DAWs) and MIDI devices can interpret to reproduce the exact timing, instruments, and performance dynamics.

**Structure of a MIDI File:**

1. **Header Chunk**:
   - **Purpose**: Defines global parameters such as the file format type, number of tracks, and the timing resolution.
   - **Format Types**:
     - **Format 0**: Single-track MIDI file where all events are stored in a single track.
     - **Format 1**: Multi-track format with events stored across multiple tracks in synchronization.
     - **Format 2**: Multiple tracks with independent timing (less common).
   - **Timing Division**: Defines the timing resolution of the file, usually in ticks per quarter note (TPQN).

   Example (in hexadecimal):
MThd 00 00 00 06 // "MThd" indicates the start of the header chunk 00 01 // Format type 1 (multi-track) 00 02 // Two tracks in the file 00 60 // 96 ticks per quarter note

- **Purpose**: Each track chunk contains a sequence of MIDI events with associated delta times, which indicate the time delay before the next event occurs.
- **Delta Time**: Stored in a variable-length format, represents the number of ticks since the previous event.
- **MIDI Events**: These include Note On/Off, Control Changes, Program Changes, and other messages.

Example of a Track Chunk (hexadecimal):
MTrk // Start of track 00 90 3C 40 // Note On: Middle C (60), velocity 64 81 00 // Delta time of 128 ticks (roughly 1 second) 00 80 3C 40 // Note Off: Middle C FF 2F 00 // End of track event

- **Reading**: Software parses the header chunk to determine file properties, then processes each track chunk to generate events in real time.
- **Writing**: DAWs or MIDI sequencers convert recorded events into MIDI file format for storage or sharing.

**Key Events Stored in Tracks**:
- Note On/Off
- Pitch Bend

Comprehensive Overview of MIDI Structure (Events, Channels, Messages)
MIDI Events
MIDI events are the building blocks of any MIDI communication, describing every aspect of a musical performance. Events are transmitted between devices or software in real-time, or recorded in MIDI files for later playback. Events can be categorized into two main types: Channel Events and System Events.

Channel Events:

Channel events affect specific channels and are associated with musical performance data, such as playing notes or adjusting sound parameters.
Channel events include:
Note On: Indicates when a note is pressed. The event includes the MIDI note number (which corresponds to pitch) and velocity (which typically represents how hard the note is played).
Note Off: Indicates when a note is released.
Control Change: Changes a specific control parameter, such as volume or modulation. Control changes are mapped to predefined controller numbers.
Pitch Bend: Allows smooth, continuous pitch variation, useful for bending notes or creating vibrato.
Aftertouch/Polyphonic Key Pressure: Indicates pressure applied to a key after it is struck, adding expressiveness to the note.
System Events:

System events are global and not restricted to specific channels. They handle synchronization, timing, and custom data communication (like System Exclusive messages).
Types of system events include:
System Common Messages: Deal with tasks like setting the song position or selecting a specific song.
System Real-Time Messages: Handle real-time synchronization, including Start, Stop, Continue, and Timing Clock messages. These are essential for keeping multiple devices in sync.
System Exclusive (SysEx) Messages: Custom messages used by manufacturers to send device-specific data. SysEx can transmit a wide range of data, such as patch information or system settings.
MIDI Channels
MIDI supports 16 distinct channels on a single interface, meaning 16 independent streams of musical data can be sent simultaneously, each potentially controlling a different instrument or device.

Channel Numbering:

Channels are numbered from 1 to 16, but in MIDI data, they are represented as values 0–15 (since data bytes in MIDI are zero-based).
Each channel can be assigned a unique instrument, such as a piano on Channel 1 and drums on Channel 10. Channel 10 is conventionally reserved for percussion in the General MIDI standard.
Channel Messages:

Every MIDI channel has its own stream of events (Note On, Note Off, etc.).
A Note On message for Channel 1 is different from a Note On message for Channel 2, allowing multiple instruments to play simultaneously without overlap.
Channel Modes:

Omni On/Omni Off: Determines whether a device listens to all MIDI channels (Omni On) or only the specified channel (Omni Off).
Mono/Poly: Controls whether a channel operates in mono mode (one note at a time) or poly mode (multiple notes simultaneously).
MIDI Messages
MIDI messages are categorized as either Channel Messages or System Messages, with the format being determined by the status byte. A MIDI message consists of a status byte and one or two data bytes that provide additional details about the event.

Structure of a MIDI Message:

Status Byte: The first byte of the message indicates the type of message and the channel number (for channel messages). The status byte always starts with a 1 in the most significant bit (MSB).
For example, 1001nnnn is a Note On message where nnnn specifies the MIDI channel.
Data Bytes: One or two bytes that provide specific information for the event. Data bytes always start with a 0 in the MSB.
For a Note On message, the first data byte indicates the note number (0-127), and the second data byte indicates the velocity (0-127).
Common Channel Messages:

Note On (1001nnnn): Sent when a key is pressed.

Data Byte 1: Note number (0–127, where 60 is Middle C).
Data Byte 2: Velocity (0–127, where 0 typically means Note Off).
Example: 90 3C 40 is a Note On for Channel 1 (status byte 90), playing Middle C (3C = 60) with velocity 64 (40 in hexadecimal).
Note Off (1000nnnn): Sent when a key is released.

Data Byte 1: Note number.
Data Byte 2: Release velocity.
Example: 80 3C 40 is a Note Off for Channel 1, stopping Middle C with velocity 64.
Control Change (1011nnnn): Alters a parameter, such as modulation or volume.

Data Byte 1: Controller number (e.g., 1 for Modulation, 7 for Volume).
Data Byte 2: Value (0–127).
Example: B0 07 40 sets the volume on Channel 1 to 64.
Program Change (1100nnnn): Changes the instrument (patch) being used on a channel.

Data Byte 1: Program number (0–127).
Example: C0 05 changes the instrument to program 5 on Channel 1.
Pitch Bend (1110nnnn): Adjusts the pitch up or down. It uses two data bytes to allow for finer resolution (14-bit value).

Example: E0 00 40 sets pitch bend to the center position.
System Messages
System messages are divided into System Common, System Real-Time, and System Exclusive (SysEx).

System Common Messages:

Song Position Pointer (11110010): Tells devices where to start playing within a sequence.
Song Select (11110011): Selects which song to play.
Tune Request (11110110): Instructs analog synthesizers to retune themselves.
System Real-Time Messages:

Timing Clock (11111000): Sent 24 times per quarter note to keep devices in sync.
Start (11111010): Starts playback of a sequence.
Stop (11111100): Stops playback of a sequence.
Continue (11111011): Resumes playback from the current position.
System Exclusive (SysEx) Messages:

SysEx allows manufacturers to define custom messages for their devices, usually for transmitting bulk data like patch settings or firmware updates.
SysEx starts with 11110000 and ends with 11110111.
Example: F0 41 10 42 12 40 00 7F F7 is a Roland-specific SysEx message.
Meta Messages (used in MIDI files)
While not transmitted during live MIDI performances, meta messages are stored in MIDI files to provide information about the file itself (tempo, time signature, etc.).

Set Tempo (FF 51 03): Specifies the tempo in microseconds per quarter note.

Example: FF 51 03 07 A1 20 sets the tempo to 120 BPM.
Time Signature (FF 58 04): Specifies the time signature.

Example: FF 58 04 04 02 18 08 sets the time signature to 4/4.
Key Signature (FF 59 02): Specifies the key signature.

Example: FF 59 02 00 00 sets the key signature to C major.
Track Name (FF 03): Sets the name of the current track.

Example: FF 03 07 Piano names the track "Piano."

2. Common MIDI Protocols and Standards (General MIDI, MIDI 2.0)
plaintext

MIDI protocols have evolved over time to improve communication between devices and to standardize the way electronic instruments and software handle musical data.

#### General MIDI (GM)
General MIDI (GM) was introduced to standardize the way MIDI devices communicate and ensure that MIDI files sound consistent across different devices. GM defines a fixed set of instrument sounds, control changes, and channel allocations.

- **Instrument Sound Set**: General MIDI supports 128 predefined instrument sounds, categorized into groups like Piano, Guitar, Bass, Strings, etc. Each instrument sound is assigned a specific program number (0–127).
  - Example:
    - Program 0: Acoustic Grand Piano
    - Program 24: Nylon Guitar
    - Program 41: Violin
    - Program 118: Synth Drum

- **Percussion on Channel 10**: In GM, percussion instruments (like drums) are always assigned to Channel 10. Each note on Channel 10 corresponds to a specific drum sound (e.g., C3 is a Bass Drum, D3 is a Snare Drum).

- **Control Change Standardization**: GM reserves certain control change messages for specific parameters, ensuring compatibility between devices. For example:
  - Control Change 1: Modulation Wheel
  - Control Change 7: Volume
  - Control Change 10: Pan
  - Control Change 64: Sustain Pedal (On/Off)

- **GM Polyphony**: General MIDI requires devices to support at least 24 simultaneous voices (notes) to ensure smooth playback.

---

#### MIDI 2.0
MIDI 2.0 expands on the original MIDI protocol, offering more expressive capabilities and greater control resolution. It introduces a new messaging format while maintaining backward compatibility with MIDI 1.0.

- **Higher Resolution**: MIDI 2.0 increases the precision of control messages and note velocities. Instead of being limited to 7-bit values (0–127), MIDI 2.0 uses 32-bit values, allowing for finer control over dynamics and articulation.
  - Example: In MIDI 1.0, a Note On velocity of 64 could be mapped as a medium dynamic; in MIDI 2.0, this would be expanded to a much more precise range.

- **Per-Note Controllers**: MIDI 2.0 allows individual notes to have their own unique control changes (e.g., pitch bend or modulation). This allows for more expressive performances, especially in polyphonic instruments.

- **Property Exchange**: MIDI 2.0 introduces a system for devices to exchange information about their capabilities, settings, and instrument profiles. This allows for automatic configuration and better interoperability between devices and software.

- **Backwards Compatibility**: MIDI 2.0 devices can still communicate with MIDI 1.0 devices, ensuring that legacy hardware and software remain useful.

---

#### Key Differences Between General MIDI and MIDI 2.0
1. **Resolution**: MIDI 1.0 uses 7-bit values for most control changes (0–127), while MIDI 2.0 uses 32-bit values for much finer resolution.
2. **Expressiveness**: MIDI 2.0 supports per-note control messages, allowing for more expressive performances, especially with polyphonic instruments.
3. **Interoperability**: MIDI 2.0 includes property exchange for better device compatibility and configuration.
3. File Formatting: How MIDI Files are Read and Written
plaintext

MIDI files (.mid) are standardized digital containers that store sequences of MIDI events. These files are read and written by software, hardware, and DAWs to capture and play back performances.

#### Structure of a MIDI File

1. **Header Chunk**: 
    - The header chunk is the first part of a MIDI file and defines global information about the file. It includes the file format type, number of tracks, and timing resolution.
    - **Format Types**:
      - **Format 0**: A single-track MIDI file where all events are merged into one track.
      - **Format 1**: Multi-track format where events are stored across multiple synchronized tracks.
      - **Format 2**: Multi-track format where each track is independent, meaning the timing between them is not synchronized.
    - **Timing Division**: Specifies the resolution of timing in terms of ticks per quarter note (TPQN). This helps the DAW interpret the time spacing between events.

    Example (in hexadecimal representation):
    ```
    MThd 00 00 00 06  // Header Chunk begins
    00 01             // Format type 1 (multi-track)
    00 02             // Two tracks in the file
    00 60             // Timing division of 96 ticks per quarter note
    ```

2. **Track Chunk**:
    - Each track chunk contains a sequence of MIDI events. The track chunk starts with a "MTrk" identifier followed by the size of the track.
    - **Delta Time**: Delta time defines the number of ticks (based on the file’s timing division) that pass before the next event is triggered. It is stored in a variable-length format.
    - **MIDI Events**: Each event describes a musical action, such as playing a note, changing volume, or switching an instrument.

    Example of a Track Chunk (in hexadecimal):
    ```
    MTrk              // Track Chunk begins
    00 90 3C 40       // Note On: Middle C, velocity 64
    81 00             // Delta time of 128 ticks
    00 80 3C 40       // Note Off: Middle C
    FF 2F 00          // End of track
    ```

3. **File Reading/Writing**:
    - **Reading**: A MIDI parser or DAW reads the header chunk first to determine the file type, number of tracks, and timing resolution. It then reads each track chunk, interpreting events and delta times to recreate the original performance.
    - **Writing**: A DAW or MIDI sequencer writes events (Note On, Note Off, Control Changes, etc.) in the correct order with delta times to ensure proper timing.

---

#### Important Events in MIDI Files
- **Note On** (`90 nn vv`): Turns on a note. `nn` is the note number (0–127) and `vv` is the velocity.
- **Note Off** (`80 nn vv`): Turns off a note.
- **Control Change** (`B0 cc vv`): Changes a control parameter (e.g., volume, pan).
- **Program Change** (`C0 pp`): Changes the instrument sound.
- **Meta Events**: Non-MIDI events used in files to define things like tempo, key signature, or track names. These include `FF 51` (Set Tempo), `FF 58` (Time Signature), and `FF 59` (Key Signature).
